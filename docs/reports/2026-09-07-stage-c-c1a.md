# 工程C C1-a 実装報告

2026-09-07 / 実装担当 / Astra初回レビュー修正後・再レビュー前

## 結論

C0のEvidenceManifest v1と実evidenceを入力に、注入済みの `ReaderContextRequest[]` を文書単位で検証し、意味審査を経た限定patch案または安全な停止結果を返す純粋helperを実装した。

本単位はC1-aのみ。既存の日次生成、prompt、LLM、外部検索、fallback、mode、review apply、保存・公開・投稿・通知には接続していない。常時運用の完成ではない。

## 入出力と安全境界

- 入力: 実 `RawArticle[]`、C0 `EvidenceManifest`、既存 `FactLedger`、モデル応答を想定した候補配列、注釈前 `SummarizedArticle`、注入した意味審査関数。
- 候補: `required / optional / not_needed` を保持。最大8件、ID、出現span長、E/document対応、原語の出現を検証する。
- support: quoteと主語quoteを同じE/documentの検証済みspanへbindする。C0 manifestの `current_input_exact_body`、`raw_content`、usable extraction、利用可能なintegrityをすべて要求する。さらに実evidence本文のhash、document ID、requested/final URLをmanifestへ再照合し、古いmanifestの流用を止める。
- `terms=[]` でも候補を落とさない。term経路でも、resolvedにするCは存在・利用可否・E・quote・scopeを検証する。spanだけ確認できCがない候補は `support_ready + claim_binding_required + held` とし、patchを返さない。
- 候補群では有効C付きsupportを優先し、Cなしterm spanは有効C付き候補がない場合だけfallbackにする。候補順によってhold/passを変えず、意味審査回数も増やさない。
- 意味審査: dependency injectionだけを用い、`pass / revise / hold / timeout` をfixtureで分岐する。意味審査後の説明は1〜100字に制限する。
- 出力: 共通schemaの `status / origin / definition_ja / claim_refs / support_spans / applicable_at / fetched_at / reason_codes` に加え、内部段階と限定patch案を返す。
- patch: C1-a正本順 `lead → what_happened → reaction_view → why_it_matters → japan_context_note` で最初の出現だけをanchorにし、summary hash、field、offset、C/E/document、正規URL、root/related scopeを含む。初出情報を意味審査へ渡し、説明済みspanも初出位置と対象概念へ拘束する。同一案は1件へ統合し、同一初出へ競合する案はすべてholdする。summary・ファイルは変更しない。
- 時点: `source_published_at / fetched_at / applicable_at` を分離する。適用時点は記事公開日から補わず、C1-aで検証できない自己申告値も採用しない。
- 停止: 根拠不足、本文欠損、保存済みsupplementだけ、AI生成・利用不能本文は `needs_research`。E取り違え、意味不一致、審査不能、時点不一致は `hold`。このhelperは検索しない。

## fixtureで確認した範囲

- 国家安全部、別機関、中国電影資料館、業界概念「短劇」、一般語「映画」。固有語のハードコードなし。
- `terms=[]`、required/optional/not_needed、lead初出、複数出現、説明済み、重複説明への追加0件。
- 同名別主体、E/document取り違え、取得時点不一致、ID不正・重複、401字span、9候補。
- supportなし、C0 unresolved_input、stored_review_supplement、AI生成本文、semantic revise/hold/timeout。
- root本文再利用時もscopeはrootのまま、元summaryの `source_count=1` と全入力byte列は不変。
- Astra初回レビューR1〜R5: C999、Cなし、別EのC、unsupported C、scope不一致、不正kind、正しいC付きterm、本文差替え、別E差替え、正当redirect、同語別ID、alias重複、競合説明、公開順、後段欄・同欄遠方・別概念の説明span、公開日/取得日/適用時点の分離。
- Astra再レビューR6: `[Cなし,Cあり]` / `[Cあり,Cなし]` の順序不変、Cなしだけ、無効Cだけ。
