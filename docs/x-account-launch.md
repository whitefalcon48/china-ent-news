# Xアカウント運用開始準備

最終更新: 2026-08-14

## 1. アイコン／ヘッダー比較の前提

Xの推奨サイズはアイコン `400×400 px`、ヘッダー `1500×500 px`。ヘッダーは表示環境によって上下各60pxほど切れることがあるため、ロゴ・顔・文字などの重要要素は中央の `1500×380 px` に収める。

ChatGPTへ次の3枚を一緒にアップロードして生成する。

1. `docs/assets/character-v2/bingtang-fullbody.png`（キャラクター正本）
2. `docs/assets/site/bingtang-hero-v2.png`（現在の挨拶ポーズ）
3. `docs/assets/site/bingtang-logo-horizontal.png`（ロゴ正本）

正本画像の衣装・髪・目・ヘッドホン・ロゴ文字は変更しない。比較時は一度に1点だけ変え、同じチャット内で「構図は維持して○○だけ変更」と依頼する。

## 2. アイコン生成プロンプト（A/B比較）

### A案 — 顔の認識性優先（推奨）

> 添付したビンタンのキャラクター正本を使い、Xプロフィール用の正方形アイコンを1枚作成してください。400×400px、円形に切り抜かれても顔・アホ毛・白いヘッドホンが欠けない中央構図、頭から肩まで、口を閉じた小さな笑顔と期待を含む目。背景は明るい氷色の単色に、ごく薄い氷のきらめきを少量だけ入れてください。細くクリーンな線画と明るいセル塗りを維持し、髪色、赤いインナーカラー、ルビーレッドの瞳、ヘッドホン、衣装を一切変更しないでください。文字、ロゴ、縁取り、影、追加アクセサリー、緑背景は入れないでください。

### B案 — 発見した喜び優先

> 添付したビンタンのキャラクター正本を使い、Xプロフィール用の正方形アイコンを1枚作成してください。400×400px、円形トリミングの内側に全要素を収め、頭から肩までを大きく配置。星のように輝く目、少し立ったアホ毛、口を開いた明るい発見の表情にしてください。背景は白から淡い氷色へのごく弱い放射グラデーション。キャラクターの既存デザインと描画スタイルは正本どおりに固定し、文字、ロゴ、追加小物、緑背景は入れないでください。

比較基準: 48px表示で「ビンタンだと分かる」「目とヘッドホンが潰れない」「ニュース媒体として騒がしすぎない」。Aを通常運用の第一候補、Bをキャラクター性が弱く見えた場合の比較候補とする。

## 3. ヘッダー生成プロンプト（A/B/C比較）

### A案 — ニュースブランド優先（推奨）

> 添付したビンタンのキャラクター正本、挨拶ポーズ、冰糖日报のロゴ正本を使い、Xヘッダーを1枚作成してください。1500×500px。上下各60pxは切れてもよい背景領域とし、重要要素は中央の高さ380px以内に置いてください。左下約300pxはプロフィールアイコンと重なるため重要要素を置かず、ロゴを左寄りの中央、片手を上げたビンタンを右側に配置。背景は白〜淡い氷色、細い水色の情報ラインと小さな赤いアクセントを少量だけ入れ、明るくクリーンな中国エンタメニュース媒体に見せてください。ロゴの文字、字体、色、キャラクターの外見と衣装は一切変更しないでください。新しい文字、コピー、実在人物、写真、追加ロゴ、緑背景は入れないでください。

### B案 — ビンタンとの距離感優先

> A案と同じ正本素材・サイズ・安全領域を維持し、構図だけ変更してください。ビンタンを右中央に少し大きく置き、こちらへ小さく身を乗り出して「見つけた話題を届けに来た」印象にしてください。ロゴは中央左に十分な余白を取って配置。背景は淡い氷色の編集デスクを抽象化した軽いカードや通知ドットだけにし、具体的な記事文字やUIは描かないでください。キャラクター、ロゴ、色、衣装は変更せず、新しい文字も追加しないでください。

### C案 — 現地の熱量を視覚化

> A案と同じ正本素材・サイズ・安全領域を維持し、背景表現だけ変更してください。白〜氷色の静かな背景に、右奥から赤と水色の小さな光点や波紋が集まり、ビンタンが「小さな熱狂」を見つけたことを示す抽象表現にしてください。ロゴは中央左、ビンタンは右側。派手なネオン、炎、群衆、実在SNS画面、読めない疑似文字は使わないでください。キャラクターとロゴは正本から変更しないでください。

比較基準: PCとスマホの両方でロゴが読める、プロフィールアイコンと干渉しない、キャラクターがニュースより前に出すぎない、サイトの氷色・赤・濃紺と連続して見える。Aを第一候補とする。

## 4. X文面の新しい契約

- 日次ダイジェスト: 日付の直後に、先頭記事の `why_it_matters` 先頭1文を `ビンタン「…」` として入れる。
- 個別投稿／持ち込み投稿: 見出しの次に同じ形式のひとことを入れる。
- ひとことは既にfact ledger・claim check・人間レビューを通った公開コメントからそのまま再利用する。X専用の新しい事実や感想は生成しない。
- 字数超過時は安全に末尾を省略し、X換算280以内に収める。`why_it_matters` が空なら従来どおりリードを使う。

例:

```text
🧊 今日の中国エンタメ｜8/14
ビンタン「この配役、原作の関係性がどう映像になるか気になります！」
・新ドラマの主要キャストが発表
・配信初日の数字が公開
ほか全5本👇
https://bingtangnews.0-w-0.net/archive/2026-08-14/
```

## 5. 公開後通知フロー

```text
レビュー採用完了
  → 本番サイトをビルド／デプロイ
  → 公開URLへHTTP確認（失敗時は通知せずIssueを開いたまま）
  → X文面を生成
  → レビューIssueへ「公開URL＋X文面」を自動返信
  → Issueをクローズ
```

日次・持ち込みの両方を対象にする。GitHubの対象IssueをSubscribeし、GitHub通知設定でメール受信を有効にすると、この自動返信がメールに届く。通知返信だけは `continue-on-error` とし、GitHub通知障害で公開済みページを失敗扱いにしない。公開URLのHTTP確認は必須のため、確認できなければIssueは閉じない。

専用メール本文・件名・送信元を整えたい段階になったら、次の拡張としてメール配信サービスを追加する。その場合も公開処理とメール送信を分離し、メール失敗で再デプロイしない。
